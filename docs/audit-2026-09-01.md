## A. Time-bound: the liveness probe self-destructs ~2026-09-22

✅ Verified. GitHub disables scheduled workflows after **60 days of repository inactivity**.
Last push `2026-07-24T10:46:03Z` (`gh api repos/…/actions/workflows` still reports the
workflow `active`, id 313428979). 60 days lands **~2026-09-22**, about three weeks out.

Why it matters: `.github/workflows/keepalive.yml` is the only thing preventing Supabase's
~7-day free-tier idle pause. When it stops, the 2026-06-15 outage repeats — and that one went
**unnoticed for about a month**.

**A commit that reaches GitHub resets the counter — a local commit does not.** The 60-day
window is measured server-side against repository activity, so this audit's commit only buys
another 60 days *once pushed*. Push path (the SSH key is passphrase-protected and unusable
non-interactively, per the 2026-07-22 devlog):

```
git -c credential.helper='!gh auth git-credential' push https://github.com/mohamedmeghawry/modest-filter.git main
```

Two further defects in the same probe:
- ✅ It targets `modest-filter.vercel.app`, not `kashfedit.com`. The `TODO` to repoint it has
  been open since the domain connected on 2026-07-22. A DNS, Cloudflare, or cert failure on
  the real front door leaves the check green — the exact "a green check tests configuration,
  not reachability" trap the devlog names twice (2026-07-14, 2026-07-22).
- ✅ `curl -sSf` has no `-L`, so a 3xx exits 0 and passes.

## B. The live site is a liability at the review it is waiting for

✅ Verified against production and `prisma/seed.ts`.

`kashfedit.com/products` publicly serves **four fabricated products attributed to real named
brands**, including *"Aritzia — Flowing Long-Sleeve Maxi Abaya"*, an item Aritzia does not
sell, linking to a constructed URL (`aritzia.com/product/maxi-abaya/2002.html`, returns 403).
Every image points at `via.placeholder.com`, which is **fully dead** — connection failure, not
a 404, so the boxes render as nothing.

The landing page was built *specifically* so an affiliate reviewer would see a credible
property (devlog 2026-07-22: "Build one before an affiliate reviewer, or anyone else, sees
it"). That reviewer's next click is `/products`. Nobody wrote down that the demo catalogue is
a liability at exactly the review the project is blocked on.

Related, ✅ verified: the affiliate anchor at `app/products/[id]/page.tsx:76` carries only
`rel="noopener noreferrer"`. **`rel="sponsored"` is missing** — required by Google for paid
links and by several networks' terms. Disclosure *copy* is already present in the footer,
`/about`, and `/privacy`; this is the one mechanical piece missing.

> The composed failure is worth naming: the domain, the landing page, and the Privacy policy
> were each individually correct moves toward "look credible to a reviewer," and each passed
> its own review. Nobody walked the reviewer's actual path end to end.

## E. Work recorded as done that isn't

**The eval gate has never actually been run.** Wargame 07 Move 3 is the go/no-go at ≥80%
overall and ≥65% per vision attribute across 28 products. The only measured numbers anywhere:
10/14 on one product (ADR-0012), 78/84 **eyeballed** on six (no scorer), and a description A/B
on 17. No document records a full scored run. This is the **largest de-risking action that is
entirely unblocked by affiliate access**, costs roughly $0.60–0.90, could invalidate
"Phase 1 done" — and is scheduled nowhere.

**✅ And it cannot score 28 as written.** Three manifest entries carry an empty second image
slot (`semisheer-scoopback`, `black-classic-abaya`, `openfront-abaya`); `scripts/eval-score.ts:96`
treats an empty path as a missing image and skips the **whole entry**, so a default run scores
**25**. Two orphaned files on disk (`everlane-denim-shirtdress_front.pn.png`,
`lined-floral-midi_back.pn.webp`) look like the mis-saved halves. Four different denominators
now circulate across the docs: 28 (wargames), 25 (actual), 22 (`--require-description`),
17 (ADR-0014's A/B).

**"Phase 1 DONE" overstates the pipeline.** ✅ Verified: `parseFeedFacts` — the entirety of
ADR-0014's production design — is imported by nothing outside its own test. `Product` has no
`description` column for it to read and no `imageUrls` column, so `tag-catalogue.ts` sends one
image per product while ADR-0012's own finding is that multi-image model-on input is what
produced 93% against 71%. The **toolchain** is done; the production path it was built for does
not exist.

**The ground truth rests on conventions marked undecided.** `docs/tagging-conventions.md` lists
six open conventions; four of them (`scoop` vs `square`, `low_back`/`open_back`/`scoop_back`,
`fit` with a belt, `slit` null-vs-none) directly set ground-truth values for attributes the
≥65% bar is applied to. ADR-0012's shared-blind-spot caveat — the same agent produced both the
truth and the predictions — is not carried forward onto the 28-product set.

**The eval images exist on exactly one disk, by design.** 56 files, gitignored via
`/samples/**/*.png|webp|…`, never in git. Lose that folder and the gate is unrunnable and
ADR-0012/0014 are unreproducible. Written down nowhere as a risk — despite a smaller version
having already happened: `samples/manifest.json` and `samples/manifest-model-on.json` are
tracked-but-deleted in the working tree, flagged in the status note on 2026-07-14, and still
uncommitted 49 days later. `npm run vision:spike` is broken for both wired paths as a result.

## F. Risks that detonate the moment Phase 2 lands

✅ All verified in `lib/data/products.ts`.

- **No pagination anywhere.** `listProducts` has no `take`/`skip`/`cursor`; `/products` is
  `force-dynamic`; `getFacetCounts` fires 7 uncached queries per request against a free-tier
  pooler. Wargame 08 targets 300–1,000 products. The page will try to render the entire
  catalogue in one grid.
- **Partial tagging will read as a broken filter.** `listProducts` and `getFacetCounts` filter
  on neither `tagStatus` nor `inStock`. Untagged products appear in the unfiltered grid and
  vanish the instant any filter is set (ADR-0008 strict-`in`; NULL never matches).
  Out-of-stock rows render with live affiliate links.
- **`Product.affiliateUrl` is non-nullable.** This is why Tier-2 scraping cannot route around
  the affiliate blocker: ADR-0013's Tier 2 solves *image adequacy*, but a product row still
  cannot be inserted without a click-through URL. Either a network supplies them, or the
  schema changes.
- **CSP will block real product images.** `img-src 'self' blob: data:` is correct only while
  nothing external renders. The only way to satisfy it is `next/image` — which makes Vercel
  fetch, optimise, cache and re-serve brand imagery from our origin, much closer to the
  republication ADR-0013's extraction-only cornerstone forbids. Both docs file this as
  "wire it up later"; neither notices they conflict.
- **No per-attribute provenance.** Wargame 07 Move 4 deliberately writes vision's *guessed*
  `material`/`lined` rather than NULL (to avoid strict-`in` exclusion), so a 71–82%-accurate
  guess is stored indistinguishably from a feed-parsed fact, with no way to find or re-tag the
  guesses later.
- **`TagStatus.verified` protects a workflow that does not exist** — no UI, script, or admin
  path lets a human correct a tag.
- **No rate limiting** on a live, public, uncached, `force-dynamic` API backed by free-tier
  Postgres. AGENTS.md lists it as mandatory before production; deferred since 2026-06-08
  pending an Upstash / in-memory / Vercel WAF decision. Casual scraping is the threat model's
  own #3 named threat, and it burns the exact quota the keepalive exists to protect.
- **RLS and the Anthropic spend cap live only in dashboards.** No migration contains
  `ENABLE ROW LEVEL SECURITY` or `CREATE POLICY`, so the still-deferred durable-host move
  (Supabase Pro vs Neon vs free+backups) rebuilds the database with RLS silently absent. There
  is no `pg_dump`/export step anywhere; the only stated recovery path is re-running
  `prisma/seed.ts`, which stops being adequate the moment ~$50 of tags are in the table.
